# 선택 가능한 과제 진행 메모

별도 실행 하네스를 설치하지 않고 제공 Codex의 작업을 짧게 정리할 때만 읽는다. 현재 공식 지시·실제 README·기존 프로젝트 지침이 우선한다. 새 추정 규칙·채점 기준·반입 권한을 만들지 않는다.

1. 현재 단계·필수 산출물·기존 작업·남은 시간을 실제 자료에서 확인한다. 확인되지 않은 시간을 추측하지 않는다.
2. 요구가 모호하면 grill-me/grilling으로 결과를 바꾸는 결정만 질문한다. 파일에서 알 수 있는 사실은 먼저 읽고, 현업 사실과 구현 선택을 구분한다.
3. 필수 입력→처리→출력의 작은 완결 흐름부터 만든다. 제공 스택을 우선하고, UI/API/DB/외부 서비스가 필요하다고 미리 가정하지 않는다.
4. 화면이 필요하면 frontend-design, 허용된 업무 API가 필요하면 api-tester, 반복 오류가 있으면 diagnosing-bugs를 선택한다. 모든 지침을 한꺼번에 적용하지 않는다.
5. 필수 조건마다 실제 확인 방법을 연결한다. 코드 수정 뒤 관련 검사를 실행한다. 완료 주장에는 verification-before-completion을 적용해 명령·전체 결과·종료 상태·미검증을 대조한다. 문서 필드나 서버 실행만으로 업무 성공을 판정하지 않는다.
6. UI는 참가자가 제공 미리보기에서 직접 확인한다. 서버가 필요하면 제공 환경에 맞는 바인딩·실제 포트·경로와 실행 유지 상태를 확인한다.
7. 기존 문서에 선택·근거·남은 한계를 짧게 남긴다. 별도 장부·고정 템플릿·의미 없는 커밋을 늘리지 않는다. 공식 제출 준비 시간을 확보하고 저장본·실행본·제출할 버전을 맞춘다.

공개 참고 자료의 설치·읽기는 결과물의 외부 반출을 허용하지 않는다. 제공 인증·Codex 버전·감독/관리 설정은 변경하지 않는다. 실제 제출 조작은 참가자가 수행한다. 단계별 AI 허용 범위는 공식 안내를 따른다.
